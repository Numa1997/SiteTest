NEON REQUEST N-1: worker/r2.js serves every stored simulation file from R2, with byte ranges

GOAL
The website Phyein Usul (https://phyeinusul.com) is a static site served by a Cloudflare Worker. Large simulation data is moving
from the git repository and from GitHub releases into the Cloudflare R2 bucket "phyein-usul-runs", bound to the Worker as env.RUNS.
Pages fetch whole files or byte ranges of them and check each part's SHA-256 against an index kept in the repository, so the Worker
needs no trust logic. Rewrite worker/r2.js so that /r2/<key> serves any allowed key from R2, with HTTP byte ranges.

WHAT THE NEW worker/r2.js MUST DO
1. /r2/<key>: <key> is the rest of the path after "/r2/", URL-decoded once. Allowed keys, exactly these four families, nothing else
   (anything else answers 404 "not found"):
   a. resonant-tunnelling/YYYY-MM-DD/runs/<name>.bin   (existing, Fig. 15; must keep working unchanged)
   b. sims/<sim>/YYYY-MM-DD-v<N>/<file>               (new engine runs; <sim> = [a-z0-9_]+, <N> = one or more digits)
   c. data/<folder>/<more path>                        (files moved from the repository keep their path under public/ as key)
      where <folder> is one of: fig12, fig16, schrodinger-sphere, resonant-tunnelling, sims
   d. simulations/fig13/dive/<file>                    (Fig. 13's dive.bin, moved the same way)
   Every path segment ("<name>", "<file>", each part of "<more path>") matches [A-Za-z0-9_.-]+, must not start with ".", and the
   whole key has at most 8 segments and at most 512 characters. No "..", no empty segment, no backslash, no "%" left after decoding.
2. Methods: GET and HEAD only; others answer 405 "method not allowed".
3. GET without a Range header: env.RUNS.get(key) -> 200 with the whole body.
   GET with a Range header: env.RUNS.get(key, { range: request.headers }) -> 206, with
   content-range "bytes <first>-<last>/<total size>" computed from the returned object's .range ({offset, length} or {suffix})
   and its .size, and content-length = the length of the part.
   A range that cannot be satisfied (first byte at or beyond the size) answers 416 with content-range "bytes */<total size>"
   (use env.RUNS.head(key) to learn the size); a Range header that is not a single "bytes=a-b", "bytes=a-" or "bytes=-n" range is
   ignored and the whole file is sent with 200.
   Missing object: 404 "not found".
4. HEAD: env.RUNS.head(key) -> 200 with the same headers as a GET of the whole file (content-length = size) and no body; 404 if absent.
5. Headers on 200 and 206: obj.writeHttpMetadata(headers) first, then set etag = obj.httpEtag, content-type
   application/octet-stream, x-content-type-options nosniff, accept-ranges bytes,
   cache-control "public, max-age=31536000, immutable" (a key is never overwritten: a new run gets a new address).
   404, 405 and 416 answers carry cache-control "no-store".
6. /rel/<tag>/<file> stays EXACTLY as it is today (the function release() below, unchanged, byte for byte): it is the old path for
   GitHub release files and is kept until nothing reads it.
7. Every other path: return env.ASSETS.fetch(request), as today.
8. Keep the file's style: plain JavaScript module, no dependencies, no TypeScript, comments in plain English explaining why, at the
   top a short comment saying what the Worker serves (the four key families and /rel/). Do not use any name of a person.

THE FILE AS IT IS NOW (worker/r2.js, whole)
```js
// Phyein Usul's Worker (see wrangler.jsonc and docs/usul.md). The site is static files (assets); this script only answers what
// the assets do not hold: the large stored simulation runs, kept in the R2 bucket bound as RUNS and served under /r2/<key>.
// Fig. 15 (resonant tunnelling, generation 2) is the first user: about 3700 run files, several GB, too large for the repository.
// The page checks every file's SHA-256 against its index in the repository, so the bucket needs no trust of its own.
const KEY = /^resonant-tunnelling\/\d{4}-\d\d-\d\d\/runs\/[A-Za-z0-9_.\-]+\.bin$/;
// Large simulation data made by the Kaggle line (docs/kaggle-sims.md, "Large data", since 23 November 2026) lives as files of a GitHub
// release of this repository, sims-<sim>-<date>. /rel/<tag>/<file> fetches it from GitHub and passes a Range request through, so a page
// downloads only the part it needs; the page checks every part's SHA-256 against the index in the repository.
const REL = /^(sims-[a-z0-9_]+-\d{4}-\d\d-\d\d)\/([A-Za-z0-9_.\-]+\.pack)$/;

async function release(request, path) {
  if (request.method !== 'GET' && request.method !== 'HEAD') return new Response('method not allowed', { status: 405 });
  const m = REL.exec(decodeURIComponent(path));
  if (!m) return new Response('not found', { status: 404 });
  const ask = new Headers(), range = request.headers.get('range');
  if (range) ask.set('range', range);
  // GitHub now and then answers a release download with an error although the file is there (seen 23 November 2026: about one request
  // in twenty came back as 404 here). So: up to three tries, and if all fail the reader gets 502 with GitHub's own status in the
  // header x-upstream-status, not a 404 that would read as "no such file".
  let r = null;
  for (let k = 0; k < 3; k++) {
    r = await fetch(`https://github.com/Numa1997/SiteTest/releases/download/${m[1]}/${m[2]}`, { headers: ask, redirect: 'follow' });
    if (r.status === 200 || r.status === 206) break;
    await new Promise((done) => setTimeout(done, 300 * (k + 1)));
  }
  if (r.status !== 200 && r.status !== 206) return new Response('the stored file could not be fetched', { status: 502, headers: { 'x-upstream-status': String(r.status), 'cache-control': 'no-store' } });
  const h = new Headers();
  for (const k of ['content-length', 'content-range', 'accept-ranges', 'etag']) if (r.headers.get(k)) h.set(k, r.headers.get(k));
  h.set('content-type', 'application/octet-stream');
  h.set('x-content-type-options', 'nosniff');
  h.set('cache-control', 'public, max-age=31536000, immutable');   // a release file never changes: a new generation gets a new tag
  return new Response(request.method === 'HEAD' ? null : r.body, { status: r.status, headers: h });
}

export default {
  async fetch(request, env) {
    const url = new URL(request.url);
    if (url.pathname.startsWith('/rel/')) return release(request, url.pathname.slice(5));
    if (url.pathname.startsWith('/r2/')) {
      if (request.method !== 'GET' && request.method !== 'HEAD') return new Response('method not allowed', { status: 405 });
      const key = decodeURIComponent(url.pathname.slice(4));
      if (!KEY.test(key)) return new Response('not found', { status: 404 });
      const obj = await env.RUNS.get(key);
      if (!obj) return new Response('not found', { status: 404 });
      const h = new Headers();
      obj.writeHttpMetadata(h);
      h.set('etag', obj.httpEtag);
      h.set('content-type', 'application/octet-stream');
      h.set('x-content-type-options', 'nosniff');
      h.set('cache-control', 'public, max-age=31536000, immutable');   // a run file never changes: a new run gets a new name
      return new Response(request.method === 'HEAD' ? null : obj.body, { headers: h });
    }
    return env.ASSETS.fetch(request);
  },
};
```

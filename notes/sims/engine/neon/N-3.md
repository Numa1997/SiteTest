WHERE THE DATA IS DESCRIBED (read-only for the loader)
The list of generations is the JSON file <base>/data/sims/generations.json, where <base> is the site root (a page passes it, default
"/"). Shape (fields the loader uses; other fields may exist and must be ignored):
{ "generations": [
  { "sim": "wave_interference2",          name of the simulation
    "date": "2026-11-23",                  day the data was computed (UTC)
    "version": 4,                          Kaggle notebook version (integer)
    "commit": "708802d...",                code commit (40 hex characters)
    "format": 1,                           data layout number; MISSING means 1
    "live_ok": true,                       false = the live check failed: never use this generation; missing = usable
    "store": "r2",                         "r2" or "repo"; MISSING means "repo"
    "run": "2026-11-23-v4",                R2 run folder; needed only when store is "r2"
    "files": { "geometry.bin": { "bytes": 123, "sha256": "<64 hex>" }, ... },
    "parts": { "dp_22_19_2.bin": { "pack": "dp_22.pack", "offset": 121756496, "bytes": 1318432, "sha256": "<64 hex>" }, ... }
                                           optional: small files packed inside big ones, read by byte range
  }, ... ] }
Addresses of a file named F in generation g:
  store "repo":  <base>data/sims/<sim>/<date>/F
  store "r2":    <base>r2/sims/<sim>/<run>/F
(<base> always ends with "/".) A packed part P is read from the address of its pack, with the HTTP header
"Range: bytes=<offset>-<offset+bytes-1>"; the answer must be status 206 and exactly <bytes> long.

WHAT simdata.js MUST DO
A classic script (no ES module, no dependencies, no build step) that defines window.SimData. Plain English comments that say why.
No person's name anywhere.
1. SimData.open(sim, opts) -> Promise of a generation object G.
   opts: { format: integer (default 1), base: string (default "/"), host: element (optional, see 6) }.
   It fetches generations.json once per page visit (shared by every open() call), keeps the entries with that sim, that format
   (missing format = 1) and live_ok not false, and takes the newest: latest date, then highest version. None: the promise rejects
   with Error("no stored data for <sim>, format <n>").
2. G has: G.sim, G.date, G.version, G.commit, G.format, G.store, G.entry (the raw entry), and
   G.url(name)         the address of a file or of a part's pack (rules above)
   G.file(name)        Promise of an ArrayBuffer: downloads the whole file, checks its length and SHA-256 (crypto.subtle) against
                       entry.files[name]; a name not listed rejects; a mismatch rejects with
                       Error("<name>: SHA-256 differs from generations.json")
   G.part(name)        Promise of an ArrayBuffer: reads a packed part by byte range, checks status 206, length and SHA-256 against
                       entry.parts[name]
   G.prefetch(names)   starts G.file or G.part for each name without waiting; failures are kept for the later call, not thrown
   Every file and part is downloaded at most once per visit: a second call for the same name returns the same promise.
3. Every successful check appends the name to the report (7). A failed check never hands data to the page.
4. Network or HTTP errors reject with Error("<name>: HTTP <status>") or Error("<name>: <message>").
5. SimData.fail(host, message): writes ONE plain sentence into the host element, in a <p class="simdata-fail">, replacing any earlier
   one from SimData, for example "The stored data for this figure could not be loaded (<message>)." It does not remove the page's own
   content. SimData.fail with no host does nothing.
6. If opts.host was given and open(), file() or part() rejects, SimData.fail(opts.host, err.message) is called before the rejection
   reaches the page.
7. Report for the live check: window.__simData is set on the first open() and kept current:
     { sim, gen: {date, version, commit, format, store} or null, sha_ok: true only after at least one file or part passed and none
       failed, files: [names that passed, in order], err: message of the first failure or null,
       all: { <sim>: the same object for each sim opened on the page } }
   The top-level fields describe the most recently opened sim. (A page's existing probe reads s.err, s.sha_ok, s.gen.commit,
   s.gen.date and s.files: keep those names.)

THE TEST tools/sims/test_simdata.cjs
Run as: node tools/sims/test_simdata.cjs
It builds everything it needs in a temporary folder (os.tmpdir()), serves it with Node's own http module on a free port (support
GET, HEAD and single "Range: bytes=a-b" with 206 and content-range), opens a test page in headless Chromium that loads the real
public/scripts/simdata.js from the repository, runs the cases below in the page, prints one line per case "PASS <name>" or
"FAIL <name>: <why>", a last line "<passed> passed, <failed> failed", exits 0 only if none failed, and deletes the temporary folder.
Fixture: generations.json with the sim "t" having
  a) date 2026-11-20 v1 format 1 store repo, file a.bin (1000 random bytes);
  b) date 2026-11-22 v2 format 1 store r2 run 2026-11-22-v2, files a.bin (other 1000 random bytes) and p.pack (5000 random bytes),
     parts x.bin (offset 1000, 300 bytes) and y.bin (offset 4000, 1000 bytes) with their true SHA-256;
  c) date 2026-11-23 v3 format 1 live_ok false (must never be chosen);
  d) date 2026-11-21 v1 format 2 store repo, file f2.bin;
  e) sim "u" date 2026-11-22 v1 format 1 store repo, file bad.bin whose listed SHA-256 is wrong.
The server stores repo files under data/sims/<sim>/<date>/ and r2 files under r2/sims/<sim>/<run>/, and counts requests per path.
Cases:
  1 open("t") picks b (date 2026-11-22, version 2, store r2), not c.
  2 open("t", {format: 2}) picks d.
  3 open("nope") rejects with "no stored data for nope, format 1".
  4 G.url("a.bin") for b is "/r2/sims/t/2026-11-22-v2/a.bin"; for d G.url("f2.bin") is "/data/sims/t/2026-11-21/f2.bin".
  5 G.file("a.bin") returns b's bytes exactly; a second call makes no second request (server count stays 1).
  6 G.part("x.bin") and G.part("y.bin") return exactly bytes 1000..1299 and 4000..4999 of p.pack, each by one Range request.
  7 open("u") then file("bad.bin") rejects with "bad.bin: SHA-256 differs from generations.json"; window.__simData.all.u.sha_ok
    is false and its err is that message.
  8 with opts.host set to a div holding a <span>keep</span>, a failed file() leaves exactly one p.simdata-fail in the div and the
    span still there; a second failure still leaves exactly one.
  9 after cases 1, 5 and 6, window.__simData.all.t is {sha_ok: true, files: ["a.bin","x.bin","y.bin"], err: null,
    gen.commit = b's commit}.
 10 generations.json was requested exactly once in the whole page visit.
 11 G.prefetch(["a.bin"]) on a fresh generation object starts the download (server count rises) before file() is called.

# Iron, Cotton and the Head: source

Why an iron ball hurts and a cotton ball of the same mass does not. Three pages, English, German and Arabic, served at
`public/portfolios/impact/index.html`, `de.html` and `ar.html`. This folder is not served.

| File | What it is |
|---|---|
| `physics.js` | The model. Iron: 91 atoms on a triangular lattice, nearest neighbours joined by Morse bonds with iron's shape (αr₀ = 3.95, Girifalco and Weizer 1959). Cotton: 18 fibres of 34 beads with stretch springs, bending springs on the turning angle, breakable Morse junctions where fibres cross, and contact repulsion with friction. Head: a plate on a spring and damper; its spring force is the scale reading. Semi-implicit Euler, Δt = 2×10⁻⁴ s (iron 5 sub-steps, cotton 2). Energy books: every damper's power is integrated into heat. `physics.cjs` is the same file for the Node checks. |
| `template.html` | The page: layout, styles, the store (`declare()`, filled by `record()` where the run is computed), drawing, playback, gauges, plots, energy chart; everything drawn is read from the store. Placeholders `{{…}}` are filled by `build.py`. |
| `datahooks.js` | The data panel's hooks for this study (`Sim.data`: groups, Read values, Check, read-back, one round = one drop), inserted after the page script. The panel itself is the site's `scripts/datalog.js`; see `docs/portfolios.md`, "The data panel of the study". |
| `text_en.py`, `text_de.py`, `text_ar.py` | Every word of the three pages, including the derivations and the parameter table. The Arabic is written in Arabic, not translated line by line; the German (23 October 2026) was translated from the English and checked key by key for identical markup, maths and numbers. |
| `build.py` | `python3 build.py` writes stand-alone pages to `out/` (they load Google Fonts; not used by the site). `python3 build.py --site` writes the three site pages with the site's security policy, the site's fonts, the back link and the language switch. Since 31 October 2026 both modes also write each page's words into the elements that carry them (`data-t`, `#sections`), as the page script still does at load with the same text, and the site pages ask for the title's face (Instrument Serif 400) with a preload; without that the page grew and jumped once its script ran (layout shift 0.83, docs/performance.md, change 5). Both load the site's shared `sim.js`, `dataset.js`, `datalog.js`, `paper.css` and `data.css` (the stand-alone pages load them from `../../../public/`). |
| `checks/` | Node scripts (CommonJS, `.cjs`, because the site's `package.json` is an ES module): `energy_books.cjs` (energy closure), `weights.cjs` (settled weights), `step_size.cjs` (time-step convergence), `walkthrough.cjs` (screenshots of opening, fall, impact, end), `site_check.cjs` (the built site through a local server: fonts, policy, outside requests, numbers read from the store), `data_panel.cjs` (the data panel: every Check, every read-back, Read values, one round, Save), `plates.cjs` and `plate3.cjs` (the four Portfolios plates). Run the browser ones with `NODE_PATH=$(npm root -g)` and the preinstalled Chromium. `portfolio_page.cjs` opens the built Portfolios page at 1100 and 390 px, screenshots the project's card and checks its links and images resolve (needs a local server on port 8766). |

Rebuild after any change: `python3 build.py --site`, then `npm run build` at the repository root, then `node checks/site_check.cjs`
against `python3 -m http.server 8766` in `dist/`.
